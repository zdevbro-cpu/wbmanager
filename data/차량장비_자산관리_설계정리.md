# 회사보유 차량 · 장비 통합 자산관리 — 설계 정리

> 목적: 웹앱 시스템 설계용 항목 정리 (DB 필드 / 기능 단위)
> 범위: 차량 + 장비를 **공통 자산(Asset) 모델**로 묶고, 유형별 속성만 분기

---

## 1. 설계 원칙

| 원칙 | 내용 |
|---|---|
| 단일 자산 테이블 | `asset` 하나에 차량·장비 공통 속성. 유형별 상세는 `asset_vehicle`, `asset_equipment`로 1:1 분리 |
| 이력은 삭제 금지 | 모든 변경은 append-only 이력 테이블. 자산 본체는 soft delete(`status=폐기`) |
| 상태는 코드값 | 자유 텍스트 금지. 상태 전이는 서버에서 검증 |
| 첨부는 공통 모듈 | 차량등록증·보험증권·검사증·매뉴얼·사진 → 하나의 `attachment` 테이블에 `(ref_type, ref_id)`로 연결 |
| 일정은 공통 스케줄 | 보험만료·검사만료·정기점검·리스만료 → `asset_schedule` 하나로 통합해 알림 로직 1개만 유지 |

---

## 2. 도메인 모델 (엔티티)

```
asset (자산 마스터)
 ├─ asset_vehicle      (차량 상세, 1:1)
 ├─ asset_equipment    (장비 상세, 1:1)
 ├─ asset_assignment   (배정/불출 이력, 1:N)
 ├─ asset_usage_log    (운행일지 / 사용일지, 1:N)
 ├─ asset_maintenance  (정비·수리·점검 이력, 1:N)
 ├─ asset_cost         (비용 발생 내역, 1:N)  ← 주유/충전, 보험료, 수리비, 과태료
 ├─ asset_schedule     (만료·점검 예정일, 1:N)
 ├─ asset_inspection   (점검 체크리스트 결과, 1:N)
 ├─ asset_incident     (사고·고장·분실 신고, 1:N)
 └─ attachment         (파일/사진, 1:N)

부속 마스터: department(부서), employee(사용자), vendor(정비/렌트/보험사), asset_category(분류)
```

## 4. 기능 목록 (화면 단위)

### 관리자
1. **자산 등록/수정** — 유형 선택에 따라 상세 폼 분기, 첨부파일 업로드
2. **자산 목록/검색** — 유형·분류·부서·상태·담당자 필터, 엑셀 다운로드
3. **자산 상세** — 탭: 기본정보 / 배정이력 / 운행·사용일지 / 정비이력 / 비용 / 첨부 / 사고
4. **배정·불출 승인** — 신청 목록, 승인/반려, 연체 목록
5. **정비 관리** — 요청 접수 → 승인 → 완료 처리, 업체 관리
6. **일정 대시보드** — 만료 임박(보험/검사/점검/리스) 캘린더 + D-day 리스트
7. **비용 관리** — 자산별·기간별·항목별 집계, 연비 추이
8. **점검 체크리스트 관리** — 템플릿 정의, 실시 결과 조회
9. **기준정보** — 분류, 부서, 업체, 채번규칙, 알림설정
10. **감가상각/장부** — 월별 상각 배치, 자산대장 출력

### 일반 사용자
1. 차량/장비 **예약 신청** (달력에서 가용 자산 확인)
2. **불출/반납** 처리 (QR 스캔 → 계기판 입력 → 상태 사진)
3. **운행일지 작성** (모바일 최적화 필수)
4. **고장·사고 신고**
5. 내 배정 자산 목록

### 배치 / 자동화
- 매일 00:00 — `asset_schedule` 스캔 → 알림 대상 추출 → 메일/알림톡/푸시
- 주행거리·가동시간 기준 스케줄 재계산
- 반납 예정일 초과 → `연체` 전환 + 알림
- 월말 감가상각 계산

## 5. 상태 전이 (검증 대상)

```
자산: 가용 ⇄ 사용중 ⇄ 정비중 → 유휴 → 매각/폐기
      (분실/도난은 어느 상태에서든 전이 가능)

배정: 신청 → 승인 → 사용중 → 반납완료
              ↘ 반려          ↘ 연체 → 반납완료

정비: 요청 → 승인 → 진행중 → 완료
```
- `사용중` 자산은 다른 배정 신청 불가 (임시대여 기준)
- `정비중` / `폐기` 자산은 배정 신청 불가
- 반납 시 `return_mileage < checkout_mileage` 검증

| 역할 | 권한 |
|---|---|
| 시스템관리자 | 전체 + 기준정보 |
| 자산관리자 | 자산 CRUD, 승인, 정비, 비용 |
| 부서장 | 자기 부서 자산 조회 + 신청 1차 승인 |

→ 데이터 범위 제한: `owner_dept_id` 기준 행 단위 필터 필요

## 7. 리포트

- 자산대장 (전체 목록 + 취득가 + 장부가)
- 자산별 총소유비용(TCO): 취득가 + 누적 유지비
- 차량별 월 유류비·연비 추이
- 부서별 자산 보유 현황 / 배정률
- 가동률 (사용일수 ÷ 기간)
- 정비 이력 및 비용 Top N
- 만료 예정 현황 (보험/검사/리스)
- 운행기록부 (세무 제출용 양식)

## 8. 설계 시 주의점

1. **계기판 수치의 단일 출처** — 주행거리를 자산 마스터/운행일지/정비이력 세 곳에서 각각 관리하면 반드시 어긋남. `asset_usage_log`를 원장으로 하고 `asset.current_mileage`는 파생값(캐시)으로만 사용.
2. **알림 로직 중복 방지** — 보험·검사·점검을 각각 다른 테이블·다른 배치로 만들면 유지보수 지옥. `asset_schedule` 하나로 통합.
3. **모바일 우선** — 불출/반납·운행일지·점검은 현장에서 폰으로 입력. QR 스캔 진입 동선 필수.
4. **첨부파일 용량** — 사고/점검 사진이 가장 빨리 쌓임. 리사이즈 + 외부 스토리지 전제.
5. **삭제 정책** — 자산 삭제 불가(폐기 처리만). 이력 데이터는 자산과 함께 보존.
6. **수량 관리 장비** — 개별 관리(1개=1레코드) vs 수량 관리(공구 10개)를 처음부터 구분. 나중에 섞으면 재설계.
7. **채번 규칙** — 자산번호 포맷을 초기에 확정 (예: `V-2026-001`, `E-2026-001`). 부서 이관 시에도 불변.

## 9. 단계별 구현 우선순위 (권장)

| 단계 | 범위 |
|---|---|
| 1차 | 자산 마스터 + 유형별 상세 + 첨부 + 목록/상세 화면 |
| 2차 | 배정/불출·반납 + 예약 충돌 검증 |
| 3차 | 운행·사용일지 + 정비이력 + 비용 |
| 4차 | 일정/알림 배치 + 대시보드 |
| 5차 | 점검 체크리스트 + 사고관리 |
| 6차 | 리포트 + 감가상각 |

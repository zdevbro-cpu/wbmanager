# 품목 마스터 설계 (원방)

> 전제: 매입 시 품목과 매출 시 품목이 달라지는 스크랩 업종 특성상,
> 일반 제조업 품목 마스터 구조를 그대로 적용하면 손익 계산 단계에서 반드시 문제가 발생함.

---

## 1. 식별 · 분류

| 필드 | 설명 / 비고 |
|---|---|
| 품목코드 | 자체 체계. 분류 의미를 코드에 반영할지 결정 필요 |
| 품목명(정식) | 세금계산서 · 전표 출력용 |
| 현장 호칭(별칭) | **필수.** 계근표 · 일보에 기재되는 명칭이 제각각이므로, 별칭 → 품목코드 매핑이 없으면 ETL 단계에서 대부분 미매칭 발생 |
| 대/중/소분류 | 철스크랩 / 비철 / 기타(폐기물 · 잔재) |
| 재질 | 철, 스테인리스, 알루미늄, 동, 황동 등 |
| 등급 | 생철 · 중량 · 경량 · 선반설 등. 재질과 분리하여 관리 권장 |

---

## 2. 단위 · 수량

- **기본단위** (kg / ton) — 하나로 고정하고, 표시 단위는 변환 처리
- **계근단위 / 매입단위 / 매출단위** + 환산계수
- **수량관리 대상 여부** — 톤백 개수 등 부수 단위가 필요한 품목 구분

---

## 3. 스크랩 업종 특수 항목 (핵심)

- **매입전용 / 매출전용 / 공용 구분**
  - 매입은 "혼합철"로 입고 → 선별 후 "중량철 + 경량철"로 출고
  - 매입품목과 매출품목을 동일 마스터에 두되, 용도 플래그로 구분

- **품목 변환(등급전환) 관계**
  - 원품목 → 가공 후 품목, 예상수율(%)
  - 이 정보가 없으면 미실현손익 계산 불가

- **감량 · 공제 기본값**
  - 불순물 · 토사 · 함수 공제율 기본값
  - 계근 시 실제값으로 덮어씀

- **기본 야적장 zone 코드**
  - 물리 태깅(구역 표지 · QR) zone 코드와 **동일 키** 사용

- **시세연동 여부**
  - 고정단가 품목 / 시세(고철시세 · LME) 연동 품목 구분
  - 연동일 경우 기준시세 코드 보유

---

## 4. 세무 · 회계

- **과세구분** 및 **재활용폐자원 의제매입세액공제 대상 여부**
  - 무자료 개인 매입 비중이 있을 경우 마스터 레벨에 반드시 보유
- **ecount 품목코드 매핑** 필드
- **세무사랑 계정과목 매핑** 필드

---

## 5. 상태 관리

- 사용여부
- 등록일시 / 수정일시
- 등록자

---

## 6. 마스터에서 분리할 항목

| 항목 | 분리 사유 |
|---|---|
| 단가 → `품목단가이력` | 적용일자 · 거래처별 · 매입/매출 구분 관리. 마스터에 단가 컬럼을 두면 과거 전표 재계산 시 값이 틀어짐 |
| 거래처별 별칭 | 거래처마다 동일 품목을 다르게 호칭 |
| 공제율 실적값 | 계근 트랜잭션에 귀속되는 값 |

---

## 7. 확정 전 운영팀 확인 사항

1. 매입 등급과 매출 등급 목록이 각각 몇 개이며, 그 사이 전환 관계가 1:1인지 1:N인지
2. 동일 품목을 거래처별로 다른 명칭으로 계산서 발행하는 사례가 있는지
3. 신규 품목 발생 빈도 — 잦을 경우 코드 체계를 의미부여형이 아닌 **순번형**으로 결정
